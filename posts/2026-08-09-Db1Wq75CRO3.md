## Caption

A knowledge base shouldn't be one big corpus that gets chunked, updated, and retrieved the same way regardless of what's in it.

Library docs synced from a GitHub repo refresh every release, a paper on speculative decoding for OCR goes out of date through a completely different way, and auto extracted info from AI logs is another different approach

Chunking all of these is also completely different (code docs and arxiv paper and auto gen wii are very different)

Retrieval should fit the data too. For very technical work keyword search is a lot stronger; for other things semantic search wins. Figuring out what fits each type of data gets you better retrieval.
